# Licensing in Klipp

How Klipp's own code and everything it contains or downloads is licensed, and where each license's notices are.
The facts per component are in **`LICENSES/inventory.json`**, generated by `tools/licenses/inventory.py`; the same
inventory is shown in the app (Settings → About → Licenses and source code). `THIRD_PARTY.md` is the readable summary.
Unresolved questions are in `docs/licensing-open-questions.md`. Nothing here is legal advice – the technical checks
show what the files say, not that a use is cleared.

## Klipp's own code

- License: **GNU General Public License, version 3** – the text is `LICENSE` (also `LICENSES/texts/GPL-3.0.txt` and
  in the app).
- Copyright: the Klipp contributors (every commit in the repository is by the project's owner, partly written with
  an AI assistant). The source files carry no per-file headers.
- **"Only" or "or later" is not settled** (see below). The README and `THIRD_PARTY.md` say "GPL v3.0";
  `rust/Cargo.toml` declares `GPL-3.0-or-later` for the JNI bridge.

### GPL-3.0-only or GPL-3.0-or-later?

What the parts of the program that come from others actually say:

| Part | What its notices say | Consequence |
|---|---|---|
| OpenDRT (ported in `engine/OpenDrt.kt`) | `OpenDRT.dctl`: "License: GPLv3"; the repository's `LICENSE` is the GPL v3 text. No "or (at your option) any later version" statement. | Only version 3 is granted. |
| spektrafilm code (ported in `engine/Spektra.kt` and `engine/FilmFx.kt`, on the GPU in `engine/FilmGl.kt`) | `LICENSE`: GPL v3 text; `pyproject.toml`: "GPLv3"; `CITATION.cff`: `GPL-3.0-or-later`. No per-file notice. | Unclear: the citation metadata says "or later", the license files don't. Treated as version 3 only until the author confirms. |
| Klipp's own code | README "GPL v3.0", `rust/Cargo.toml` "GPL-3.0-or-later" | Owner's choice. |

So the **program as a whole can be conveyed under GPL-3.0**, and it **cannot be offered under "or later" as a
whole**: the OpenDRT port (and possibly the spektrafilm port) grants version 3 only. Klipp's own files could be
"or later" individually, which does not change what the combined app is under. `rust/Cargo.toml`'s
`GPL-3.0-or-later` was left as it is – making it `GPL-3.0-only`, or stating "or later" for Klipp's own code in the
README, is the owner's decision (listed in the open questions). Nothing should be relabelled "or later" because one
manifest says so.

### Selling the app

- The GPL does not require the APK to be free of charge: "You may charge any price or no price for each copy that you
  convey" (GPL-3.0 §4). It requires the **Corresponding Source** to be available to the recipients (§6) and forbids
  imposing further restrictions on the rights the GPL grants (§10).
- **Recipients keep their GPL rights**: anyone who gets the APK may copy, modify and redistribute it – also for free –
  under the GPL, and may build it from source. The app says so in Settings → About.
- How the source is provided for each release: `docs/source-release.md`.

The GPL does not cover these files; they ship beside the program ("aggregate", GPL-3.0 §5) under their own terms,
which travel with them.

## Notices that must travel with the binary

The release APK contains, under `assets/licenses/` (copied from `LICENSES/` at build time):

- the GPL-3.0 text, Apache-2.0, MPL-2.0 and the other license texts in `LICENSES/texts/`;
- every Rust crate's own license files (`LICENSES/third-party/rust/<crate>-<version>/`), FilmCraft's and
  craft-libs' `NOTICE`, the engine's font licenses, whisper.cpp's `LICENSE`/`AUTHORS` and the notice embedded in a
  compiled ggml file, libc++'s LLVM notice;
- `inventory.json`, which the app's license screen reads.

The fonts' and spektrafilm's license files ship in their own asset folders. Symphonia (MPL-2.0): the APK says where
its source is (crates.io, and Klipp's source package) – MPL-2.0 §3.2(a).

## Keeping it right

- `python3 tools/licenses/inventory.py check --gradle-deps <file>` (run in CI) fails when a Rust crate, a Maven
  artifact or a file in `app/src/main/assets` has no reviewed entry.
- After a dependency or asset change: review the new component's actual license files, add it to
  `tools/licenses/manual.json` (`rust_reviewed`, `entries`) or `tools/licenses/maven-reviewed.json`, then run
  `inventory.py build`.
